# PI-02/A source-level HTTP status and framing checkpoint

Scope: CT-01/02/10/15 at TeddyCloud source revision `d816c2c4f87c41334269c306ca05add0a1658c3f`. These are code-path conclusions, not recorded wire responses. Only synthetic/disposable requests are in scope; no device, cloud, production or credential replay.

The framework initializes `response.statusCode=200` and a URI-derived MIME type before calling the request callback ([framework initialization](../../../src/cyclone/cyclone_tcp/http/http_server.c#L550-L560), [response defaults](../../../src/cyclone/cyclone_tcp/http/http_server_misc.c#L753-L775)). The router matches method and **prefix**, then calls the first server-type-eligible handler; `ERROR_NOT_FOUND`/`ERROR_FILE_NOT_FOUND` invoke its 404 callback, but the generic 500 callback is commented out ([dispatch](../../../src/server.c#L522-L540), [404/500 callbacks](../../../src/server_helpers.c#L800-L824)). A returned `ERROR_FAILURE` must therefore not be described as a proven HTTP 500. The framework's later error switch handles selected errors and can close without an error response for other codes ([framework error switch](../../../src/cyclone/cyclone_tcp/http/http_server.c#L606-L639)).

`httpPrepareHeader` reinitializes status to 200, sets the requested Content-Type and length, enables keep-alive and disables chunking; `httpWriteResponse` writes the header, then exactly `size` body bytes and flushes ([helpers](../../../src/handler.c#L992-L1035)). The framework emits Content-Type when set, but emits Content-Length only on nonchunked persistent responses ([header formatter](../../../src/cyclone/cyclone_tcp/http/http_server_misc.c#L921-L955)). Thus configured length and observed wire header are distinct claims. A successful write does not prove complete delivery after stream failure.
