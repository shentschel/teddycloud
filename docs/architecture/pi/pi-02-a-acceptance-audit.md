2. Add digest and explicit framing version for the positive CT-15 binary request/response; keep expected bytes labeled synthetic until B validates them.
3. Reconcile CF-01 before/after file-state fixture, CF-03 source/auth negative and collision semantics, plus the deferred-route/alias/fallback coverage boundary against the inventory. Do not upgrade a route's disposition merely because one example exists.

The [review](pi-02-review.md) calls the manifest reasoned, while cataloged rows carry `-`; it also correctly says runtime conformance is not established. The [status note](pi-02-status-framing.md) leaves generic errors and invalid protobuf **wire status unknown**. The [negative catalog](../../../tests/fixtures/compatibility/ct-negative-status.json) contains absent-plugin-directory and truncated-protobuf source cases, but its invalid-protobuf parser outcome has not been exercised. No fixture should be treated as a captured HTTP status/body or device/cloud qualification.
